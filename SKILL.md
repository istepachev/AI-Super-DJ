# AI Super DJ

## Execution and cache policy

Use `make` without a persistent audio cache by default. Its engine scratch files require temporary disk space and are removed on success or failure. Keep models, history, reports and delivered masters outside that scratch area. Enable a persistent content cache only when the user chooses its location or has already configured `cache_mode: persistent` and `cache_root`; an explicit `--no-cache` overrides it. Do not repeatedly ask this workstation's user for an already chosen location. Reuse verified stages automatically after interruptions with caching enabled. Use bounded jobs for independent deck renders and only configured available GPU devices. Share decoded PCM only at identical decoder/format settings. Overlap-only correction previews require a fresh full-deck render and audit; retain the ordinary correction path when a preview cannot be confirmed. Do not change musical decisions, neural precision, sync tolerances or FLAC compression to claim faster processing. Read [references/performance.md](references/performance.md) for commands, storage limits and measurements.

Preparation reuses checkout-scoped CPU workers and may overlap with source analysis when their combined RAM estimate fits. `cpu_jobs` / `--cpu-jobs` independently bounds preparation, loudness checks and full-deck rendering; retain the configured model/device queues and resource admission. Benchmark increased CPU concurrency before retaining a workstation preference. Default scratch is local system temporary storage, independently of persistent cache; `scratch_root` may explicitly select another private work location. Keep planner inputs unchanged until ordering completes. Retain full-deck stretching: cropped context has not established PCM equivalence. Assembly must retain every verified overlap exactly. Before delivery, verify recognized shared-clock attacks after mastering and compare every decoded FLAC sample against the declared master/gain/quantization. Failed or ambiguous checks stop verified delivery. These checks preserve measured evidence; they do not establish a universal guarantee of musical quality or recognize every possible percussion event.

Independent final overlap estimates may use two configured GPUs when jobs and available host memory permit; CPU and single-GPU configurations retain serial handling. Completion-driven rendering keeps a bounded queue and delivers results in the original order. Within one overlap or acoustic audit, reuse content-checked frequency/attack bands in bounded RAM only; any PCM, format or filter change requires new preprocessing. Keep all candidate gain curves, attack-template correlations, coverage checks and timing tolerances unchanged.

The pinned master's independent LRA windows may run in bounded CPU threads after an exact upstream function check, retaining each window's filter reset and arithmetic. Master rhythm verification and encoding may overlap when resources permit; keep exports private until both complete, preserve previous outputs on failure, and retain all independent decoder/sample checks. Unsupported adapters or insufficient resources retain serial execution.

Ordinary builds admit work against available RAM, configured GPU availability and aggregate temporary/output space; concurrency may decrease, audio precision does not. Estimates are not reservations. The audited master may compile only its float64 limiter-envelope loop without fast-math or disk JIT caching; unsupported compilation retains the upstream loop. Actual overlaps have internal sustained energy-loss, estimated vocal-conflict and rhythm-coverage gates. Quiet source breaks and missing vocal estimates remain explicit uncertainty. A failed automatic window can try at most two nearby alternatives of the same overlap length, preserving order, source/playback limits and user locks. Failed alternatives never authorize a shorter transition or weaker timing threshold. The internal evidence does not need a human-facing report. Read [references/revisions.md](references/revisions.md) for repairs and track removal.

Deliver listenable audio, retaining originals and recording actual processing. One input file means enhancement and mastering; several files or a folder mean a mixed set. Use the current installed `superdj make` for new sets on a prepared workstation; retain older frozen engines for deliberate reproduction. Read [README.md](README.md) for commands, [references/workflow.md](references/workflow.md) for detailed checks, and [THIRD_PARTY.md](THIRD_PARTY.md) before changing a backend.

Optionally read private `~/.cache/superdj/runtime.local.json` for workstation paths. Keep audio, playlists, external model weights, private fitted profiles, caches and reports outside the source repository; only portable parameters and intentionally published reusable resources belong in it. Installing instructions alone does not install engines or weights. For first installation or a friend's reproducible DJ Zhilin setup, read [references/friend-setup.md](references/friend-setup.md). A fresh runtime uses DJ Zhilin. An explicit style wins over the workstation preference; `default_style` can select another style for subsequent calls. Do not infer another workstation's default from this machine's private config.

## Audio input without per-format setup

Use the same configured FFmpeg decoder for source analysis, CUE-DETR input, preparation and stems. The neural cue worker receives the executable path explicitly; never make M4A/AAC depend on `librosa.load`, audioread, system codec packs or changes to PATH. `superdj.audio` reads the actual container and first audio stream, including mislabeled/double extensions. Ordinary folder selection recognizes the shared `AUDIO_EXTENSIONS` list, including MP3, FLAC, WAV, AIFF/AIFC, M4A/M4B (AAC or ALAC), AAC, Ogg/Opus, WMA, APE, WavPack and audio-containing MP4/MKA/WebM. No separate codec installation is needed on the prepared workstation. Read [references/audio-formats.md](references/audio-formats.md) for the decoder contract and verification. A new computer still needs the initial engine/model preparation; do not represent a Markdown-only skill install as a bundled workstation runtime.

## Preserve musical intent

Keep a supplied order (`fixed`, or `make --keep-order`). Otherwise propose a sequence using harmony, tempo, energy and transition regions. Respect locked positions, approved cues and protected ranges; do not silently omit tracks. A requested count, such as twenty tracks from a larger folder, requires an explicit selection manifest before rendering: `make` consumes all eligible folder inputs after history filtering and does not implement a count limit. For requested random selection retain its seed and selection in the private manifest.

For a requested set duration such as "about one hour from this folder", select sources into a private playlist first and estimate the rendered duration including overlap subtraction. Report the achieved duration; `make` has no total-duration flag. Preserve all explicitly required tracks. A request to retain a particular chorus or passage adds a protected source interval when identifiable; it is an optional instruction or later listening correction, not a mandatory question before ordinary folder builds. The ordinary central-core selection remains automatic and is not a verified chorus recognizer.

For ordinary automatically ordered sets prefer a slower, lighter start and a faster, denser, bassier finish. Use the existing `build` development; a long set can use `wave` for a climb, breathing valley and another climb to the strongest finish. The planner applies position preferences to native BPM, measured intensity and bass, alongside transition feasibility. Treat these as a musical arc, not a requirement to increase every next track or force a playback-speed change. Use gain-invariant sound descriptors rather than file loudness for intensity/bass; they remain engineering proxies. Missing measurements contribute no guessed preference. Preserve explicit order and endpoints ahead of the arc.

For DJ Zhilin use Mood harmonic ordering by default, alongside the existing tempo/energy objective and build arc. Other styles retain Classic by default. An explicit `--harmonic-mode classic`, `mood` or `fuzzy`, or a configured `default_harmonic_mode`, takes precedence. Preserve fixed order and locks. Mood changes directed key preferences, including selected energy-boost relations; it does not measure perceived excitement or guarantee a dynamic set. For a requested rise/valley/rise use an explicitly selected wave arc rather than silently changing the development. For standalone ordering or next-track tools, read [references/harmonize.md](references/harmonize.md). Source analyses and actual remaining pools must match before comparing orders. Keep uncertainty in missing keys explicit. Retain a working profile when a new candidate regresses on the same fixed references and settings; a new observation set may change its measured score.

Treat beats, downbeats and phrases as separate evidence. Beat This! predicts beats/downbeats; CUE-DETR proposes structural cues from the source spectrogram. Fuse model suggestions with structural changes and the bar grid. Preserve imported reviewed cues even when the model disagrees. Counting sixteen bars alone does not identify a phrase. Record actual model execution, hashes, uncertainty and exceptions. Read [references/engines.md](references/engines.md) for setup and fusion details.

## Default mixing

Smooth musical transfer is a factory requirement for every ordinary style and every harmonic ordering mode (Mood, Classic and Fuzzy). Fade actual bass, accompaniment and percussion gradually; never repair a collision by automatically cutting, muting or abruptly switching the rhythmic foundation. Validate each band's effective handoff after routing, independently of attack timing and total overlap length. Ordinary SYNC bass spans at least eight shared beats within the available overlap; DJ Zhilin retains its wider reference, with a sixteen-beat minimum within the overlap. Shorter explicitly reviewed band settings still require continuity checks. If gradual routing fails the unchanged rhythm/energy checks, choose another compatible source window and rebuild. Deliberate abrupt effects require an explicit user request and are outside ordinary factory mixing.

An accepted neural 4/4 decode may coexist with low whole-recording meter consistency. Retain the whole-grid uncertainty and evaluate actual local windows: existing beats/downbeats must agree on every four-beat bar, with the same local neural contrast and timing thresholds. Do not invent bars, overwrite a declared different meter, or mark a locally supported source as human reviewed. Distinguish unavailable input files from source-window or rendered-audio failures when reporting an interrupted build.

For newly built sets use DJ Zhilin as the standard transition style. All shared-SYNC styles use the same timing principle: both decks follow one integrated tempo curve and one beat phase throughout the overlap. Prefer long compatible windows, usually thirty-two bars, sixteen for large tempo changes. Reduce automatic windows when evidence or a short source requires it. Preserve reviewed montage decisions and explicit locks.

Matching BPM alone is insufficient. Main sections retain native tempo. Choose the energetic central core using structural cues and audio features; do not play a whole extended intro/outro by default or assume numbered DJ cues exist. Target 180–240 seconds of full playback per track, including its incoming and outgoing overlaps, with a hard 300-second maximum verified against actual rendered frames. Solo time is the remaining body, not a separate three-to-four-minute allowance. Long playback requires an explicit user request for that set: pass `--long-play`, optionally `--track-play-seconds`; never enable it from workstation state or silently raise the cap to fit cues. The full-play floor is 60 seconds. Playback of 1:50 or 1:30 is a valid exception to the 3–4 minute target and must not stop a set. For a track below 120 seconds, attempt a supported optional phrase loop toward two minutes; if no clean candidate passes, retain its native playback at or above one minute. Never invent beats or add silence. Automatic folder selection excludes native files below one minute with a private named exclusion ledger; report those omissions. Explicitly required files remain required and may need a supported loop or a different source span to reach the one-minute floor. Report exact solo, deck and overlap durations separately. See [references/transition-preferences.md](references/transition-preferences.md).

Apply an optional whole-phrase loop identically to the prepared mixture, voice and drum estimates. Before editing, require the same stereo sample timeline: sample rate, frame count and floating-point PCM. Keep originals intact and record which preparation streams received the edit. An unchanged drum estimate cannot describe a repeated mixture. Loops use real stable 1/2/4/8/16-bar regions inside the solo body, with at most four copies and sixty added seconds. Preserve protected material, source locks and the native ending. Assess native harmony, active bass coherence, level change, vocal risk and actual join energy. Cross bass and melody with separate complementary frequency curves before the copied downbeat, retaining the sample timeline. These are conservative signal proxies, not a guarantee of an inaudible join. Retain a failed optional candidate's native short play instead of forcing repetition. Save the exact changed native join context with a checksum so revisions can recover the original preparation, including its modified prefix.

Keep original-source cue search separate from a repeated preparation timeline. On a failed window, map physical event rejections back to the original source and prepare any bounded repeat afresh for the next candidate. Revisions restore the recorded native timeline before decoding originals; retain raw rendered evidence and the actual successful preparation in the final manifest.

For explicitly selected `--style sync`, use separate bass, middle and high-frequency curves tied to the shared beat phase. Pass bass over at least eight beats near the middle, within the available overlap. Softly transfer mids over eight to sixteen beats; initially attenuate the incoming mids and avoid holding two dense mid parties together. Highs use a gentler cross throughout the overlap. The default DJ Zhilin uses the broader packaged curves described below. Paired band gains never exceed unity. Do not compensate attenuation by raising the entire incoming deck.

Use measured bass availability when selecting automatic windows: the outgoing source should support the handoff and the incoming source should already carry bass there. Avoid bass-empty intro/outro regions while allowing short musical fills. The 35–180 Hz profile is an energy proxy, not a kick detector; reviewed quiet cues remain constraints. Check the actual rendered overlaps for energy holes before delivery.

When local Demucs estimates are available, prefer cues with less competing vocal activity and selectively hand over foreground estimates. Apply the same timing and linear preparation to mixture and voice estimates. Bypass subtraction when estimates cannot be aligned or one voice is insignificant. Stems contain leakage; inspect vocal interference in the actual result.

Refine coarse beat labels against repeated primary percussion attacks in the source, preferably with available drum estimates. Establish a supported native clock before cutting automatic source windows. Keep displaced native figures separate, and infer missing timing controls from the supported rhythm rather than returning to noisy labels. Reject a correction-rate swing above five percentage points over a bar; this limit is a safeguard, not a desired modulation. Preserve the shared musical curve, explicit locks, protected material and overlap lengths. Check actual rendered PCM against the shared clock and directly compare both decks throughout the overlap. A maximum measured error matters even when only one beat misses; averages and accurate mathematical anchors cannot certify coincident attacks. Missing or ambiguous measurements remain explicit coverage gaps, and zero coverage must stop delivery as verified SYNC. Re-render from original float audio, retain the best measured candidate, and apply its final map to voice estimates too. Never shorten an approved transition to conceal a timing error. Read [references/acoustic-sync.md](references/acoustic-sync.md) when diagnosing or repairing drum collisions.

Match the measurement signal to the processed signal. Drum estimates may discover source events, but a rendered mixture must also use reference templates from the exact prepared native mixture sent to the stretcher. Baseline-test estimate signatures in that native mixture before requiring them in the output. Before a newly recovered bass candidate enters primary source controls, require a unique native mixture reference or an independently visible estimated percussion signature, with correlation at least 0.90 and alternative-peak margin at least 0.02. Unknown candidates retain private source evidence and explicit coverage gaps; they cannot authorize primary timing controls. Use a gradual estimated percussion handoff while retaining the approved harmonic overlap; uncertainty must not silently become a one-beat rhythm cut. This source classification executes before the first stretch, never in response to a failed output. Certified recovered attacks retain all existing output and blend requirements. Retain independently visible percussion signatures as additional checks; masked or ambiguous isolated signatures remain uncertainty. Never edit native audio merely to make a mixture resemble a separation estimate. A reassuring fresh separation must not erase a genuinely late own-source attack. When the exact known other deck independently explains a raw mixed peak, preserve that identity ambiguity and require the same native reference in the actual own contribution, with unchanged timing, correlation and coverage checks. A fresh view of the own contribution may reveal an otherwise unrecognized signature; it cannot override an eligible late own match. Check the worst paired primary/bass error after attribution. See [references/acoustic-sync.md](references/acoustic-sync.md) for the strict attribution evidence and numerical master-boundary comparison.

Preserve musical pitch during ordinary timing correction. Fractional-delay resampling of a whole deck or the finished blend changes playback speed and pitch even when its map stays within the timing-rate bound. Ordinary rendering disables both residual resampling paths. Rerender with the pitch-preserving backend or select another compatible source window at the same timing tolerance and overlap length. The advanced `allow_pitch_changing_residual` option requires explicit selection of that effect; it must not become a hidden sync repair.

Inspect coverage gaps at the user's complained-about time, even when neighbouring recognized hits pass. Independently recover established same-source bass attack shapes missed by the primary detector; recovered events must pass both rendered PCM and actual combined-waveform checks when audible. Keep primary and bass observations separate, and retain contradictory timing evidence. Check both audible decks in the final percussion audit, including a deck without a selected upper-front family. Distinguish backend displacement from fills and offbeat attacks already present in the source; accurate main hits do not guarantee that two percussion figures blend. Prefer another compatible entrance of the same approved length for a conflicting figure. Ordinary rendering disables local copies of native attack fragments: if stretching loses a supported identity, choose another compatible source window. The advanced native-attack preservation API requires explicit selection, identical foreground routing and fresh PCM checks; its local joins remain musical uncertainty.

Calibrate supplementary bass timing against the native input before rendering, with or without drum estimates. Native-ambiguous bass references remain unverified in deck/blend evidence and cannot drive timing correction from a newly unique output correlation. Preserve their proposed offsets privately. Known native-supported timing contradictions remain failures. Require the available natively observable bass references (up to eight) and every certified recovered hit in each observable view. This supplementary coverage does not replace the existing primary/paired attack requirements. A view without measurements has a null maximum and explicit uncertainty, never a zero-error alignment claim.

## DJ Жилин transitions

Waveform recognition does not prove metrical assignment: retain displaced native fills/ghost notes in the source rhythm rather than snapping every familiar attack to a quarter beat. Inspect `native_rhythm_observations` and actual frame-slope audits. The renderer remeasures local rates against the intended musical curve after source refinement, backend compensation and before delivery; an old pre-refinement statistic cannot authorize a distorted map. Unsafe edits are rejected. See [references/acoustic-sync.md](references/acoustic-sync.md).

When leading fronts are unresolved or native figures conflict, every ordinary style attempts a smooth complementary estimated-percussion transfer spanning at least eight shared beats, retaining the approved harmonic curves and overlap. The actual combined waveform must pass the unchanged timing checks; unresolved collisions require another compatible window. Validate the actual percussion gain span separately from accompaniment: broad bass/middle curves cannot certify a one-beat rhythm cut as smooth. Abrupt sequential percussion is an explicitly selected effect through the advanced blend API, not an automatic repair. Estimated separation remains approximate; audit audible weak outgoing attacks down to gain 0.05.

Keep accompaniment continuity separate from drum ownership. A brief drum transfer must never become a brief transfer of the entire bass and middle. Verify the actual bass/middle gain spans after routing, and retain a gradual musical handoff. Reviewed per-edge `handoff_windows` can position broad smooth curves within the unchanged shared clock; their exact gains must also feed vocal and combined-waveform checks. If the combined rhythm fails, the renderer can try up to three other positions of the same gradual bass/percussion transfer before changing source windows. This applies to ordinary styles, preserves overlap and transfer lengths, middle/high curves and timing checks, and never overrides an explicit bass position or width. Failed positions cannot authorize an abrupt cut. A sample-smooth cut or reassuring attack statistics do not establish a smooth musical transition.

When a kick has a bright leading transient and a later dominant bass body, compare coherent source attack families in separate bands. Do not certify the whole attack using only the strongest bass-body template. Retain the selected band and front/body offset in provenance; weak or conflicting front evidence remains unresolved. For a reviewed percussion collision, fresh drum estimates of the final timed, foreground-processed decks can transfer the entire percussion spectrum with the bass envelope while melodic beds keep their broad mid/high curves. Never subtract estimates from an earlier timing map. Source separation is approximate: inspect the actual mixed overlap and use listener feedback ahead of reassuring template numbers.

Leading-attack verification belongs to every ordinary shared-phase style. The renderer automatically requests final-deck drum estimates when a coherent earlier upper front was selected, a missed bass attack was recovered, or the supported source evidence calls for a gradual percussion transfer; it retains each style's harmonic curves while transferring the entire estimated percussion spectrum gradually. The configured local Demucs runtime is required for that detected case. No separate skill invocation or transition flag is needed. Choosing `default_style: zhilin` makes this style the workstation default; a fresh installation still needs engines and model weights. Record actual routing and uncertainty: estimated percussion transfer does not certify unresolved fronts or every possible attack.

For every ordinary shared-phase overlap, verify recognized primary and bass attacks from both audible decks in the actual combined waveform and retain `blended_front_audit`, including coverage and any explicitly selected advanced local correction. Deck timing alone cannot establish that the final mix passed. Preserve attack identity when comparing a shorter initial-front template view; repeat the master/export checks after a correction. See [references/acoustic-sync.md](references/acoustic-sync.md). Do not infer completion of earlier musical-set audits from this engine capability.

A plain `make` uses this style on a fresh workstation. Use `--style sync` for ordinary F/SYNC curves; a workstation preference or explicit style may select another supported option. Prefer thirty-two-bar compatible overlaps. Spread the middle-frequency handoff across almost the entire overlap: the incoming texture appears well before the bass handoff and the outgoing texture remains afterwards. Transfer bass slowly over about one eighth of the overlap (four bars in a thirty-two-bar transition), retaining at least sixteen beats within shorter available overlaps; highs cross gently throughout. Complementary band gains prevent two full-level foregrounds. Use the packaged approved normalized envelopes by default; [assets/zhilin-reference-v1.json](assets/zhilin-reference-v1.json) is the same portable reference without source identities, cues or feedback. A private `zhilin_profile` explicitly overrides it and its path/hash must be recorded. A configured missing profile is an error, not a silent substitution. Shared SYNC, vocal alignment and rendered-attack checks still apply. Preserve approved durations/cues, including forty/forty-four bars and explicit partial-bar beat counts. Source availability and protected material may require shorter overlap. This is an adaptation of the approved native reference, not a guarantee of identical sound on different music. Details are in [references/engines.md](references/engines.md).

## Sound and delivery

For the user's adaptive-middle preference, assess the actual synchronized overlap rather than whole-track key alone. Prefer up to thirty-two bars where the sources support each other harmonically and rhythmically. Preserve useful midband percussion/accompaniment over an otherwise empty kick section. Different chroma or uncertainty alone must not force a shorter handoff. Shorten smoothly for competing foreground voices, persistent discordant tones or conflicting melody parties in the same band. Diagnose low-frequency attack collisions separately: a shorter bass cross can retain the approved long middle; do not move a deck without trustworthy attack evidence. Explicit user audition overrides signal heuristics. The engine accepts per-edge `mid_handoff_bars` and `bass_handoff_beats` for DJ Zhilin while preserving the other bands. Read [references/adaptive-mids.md](references/adaptive-mids.md) and configured private `adaptive_mid_feedback` for reviewed examples. Local chroma/interval measures remain uncalibrated proxies, not pleasantness probabilities. Freeze predictions before listening feedback; preserve timing and compare only the band being tested. Training on one reviewed set does not establish accuracy on new music.

Decode originals to float PCM. Repair identified DC/noise defects selectively, use restrained content-dependent EQ, and bypass unnecessary processing. Avoid stacked aggressive per-track masters. Make one complete-set master with headroom; preserve native sample rate for single-file processing and declare set resampling.

Export explicitly configured twenty-four-bit FLAC; MP3 is an optional listening copy. Independently check the entire encoded file: decode, sample rate, channels, bit depth, duration, integrated loudness, sample peak and oversampled true peak. FLAC preserves the processed signal without another lossy encoding stage; it does not reconstruct information removed by MP3.

Deliver audio, timed track list for a set, private processing provenance and a brief verification report. Keep the user's audition/ranking separate from measurements. Compare excerpts at matched loudness. A plan or synthetic test alone is not a completed musical set.

Name ordinary folder-set outputs `YYYY_MM_DD_FolderName`, using only the date and main source folder name; do not append the track count. Preserve explicitly requested existing names and dates on revisions. Deliver only the music file and a relative-file CUE to configured `delivery_root`. Keep reports, analysis, intermediate audio and backups under `private_output_root`. CUE chapters must reflect the actual rendered starts and resolve the delivered filename. Preserve an existing version privately before an explicitly requested replacement; ordinary new runs choose a version suffix instead of overwriting.

Exclude previously used tracks during automatic folder selection using private `track_history`, seeded from the user's ready-folder CUE files and verified completed manifests. Match normalized artist/title/version and available source hashes; CUE-only history cannot identify arbitrary renamed recordings. Register only completed exports, and keep a human-readable index in `_Индекс_треков/Использованные_треки.txt`. Refresh ready-folder CUE history before selecting a new set. Preserve explicitly requested tracks and revisions; use `--allow-repeats` only when authorized. If fewer unused tracks remain than requested, explain the shortfall rather than silently repeating.

For an existing project or exported CUE/audio, read [references/project-archive.md](references/project-archive.md). The advanced preserving rewrite API changes specified fields in a new archive and checks retained members; application import and reproduction of automation remain separate checks. Keep this capability out of the ordinary one-file/many-file flow.
