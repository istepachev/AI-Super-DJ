# Установка и переносимый DJ Жилин

AI Super DJ состоит из инструкций для агента и локального Python-движка. Установка навыка в Codex не устанавливает Python, аудиоинструменты, нейросети или их веса. DJ Жилин — режим этого же навыка. Свежий `make` без настройки стиля использует обычный F/SYNC; явно указанный `--style zhilin` или приватный `default_style: zhilin` выбирает широкие кривые DJ Жилин.

## Запрос первой подготовки

Вставьте этот запрос в Codex на компьютере друга:

```text
Используй $skill-installer и установи ai-super-dj из корня репозитория
https://github.com/istepachev/AI-Super-DJ с именем ai-super-dj.
Затем прочитай references/friend-setup.md и подготовь локальный движок
на этом компьютере: Python 3.12, совместимые FFmpeg/FFprobe и Rubber Band,
Beat This!, CUE-DETR, Demucs и проверенные внешние обработчики.
Выбери подходящие CPU/CUDA сборки PyTorch. Создай приватный
~/.cache/superdj/runtime.local.json с реальными путями этого компьютера,
default_style: zhilin и zhilin_profile на assets/zhilin-reference-v1.json
из установленной версии. Создай мои собственные каталоги результатов,
кэша и историю использованных треков вне исходного репозитория.
Не копируй чужую музыку, историю, отзывы или настройки конкретных пар.
Проверь зависимости и явно укажи, какие модели уже готовы, а какие
потребуют загрузки при первом запуске. Сохрани версию кода и настройки.
```

Codex может установить навык из другого репозитория через `$skill-installer`; если он не появился, перезапустите Codex. Для распространения через каталог плагинов нужен отдельный пакет плагина. Сам GitHub-репозиторий с `SKILL.md` позволяет локальную установку навыка. [Официальная инструкция OpenAI](https://learn.chatgpt.com/docs/build-skills).

## Подготовка движка вручную

Ниже команды из отдельного checkout AI-Super-DJ. Установите **Python 3.12** с [официальной страницы Python](https://www.python.org/downloads/) и создайте виртуальное окружение: на Windows — `py -3.12 -m venv .venv`, на macOS/Linux — `python3.12 -m venv .venv`. Активируйте `.venv` способом вашей оболочки. Все следующие `python` и `superdj` должны относиться к этому окружению.

Установите [FFmpeg/FFprobe](https://ffmpeg.org/download.html), [Rubber Band CLI](https://breakfastquay.com/rubberband/) и [Git](https://git-scm.com/install/); для Windows есть [официальный установщик Git](https://git-scm.com/install/windows). Инструменты должны быть в PATH или заданы по абсолютным путям. Нужен именно исполняемый Rubber Band, а не только Python-обёртка. Получите исходники:

```text
git clone https://github.com/istepachev/AI-Super-DJ.git
cd AI-Super-DJ
```

После создания и активации окружения установите согласованные версии PyTorch. Пример для CPU на Windows/Linux:

```text
python -m pip install --upgrade pip
python -m pip install torch==2.3.1 torchvision==0.18.1 torchaudio==2.3.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e ".[grid,repair,cue,stems]"
superdj setup --components ../superdj-work/checkouts --download-model --cache ../superdj-work/cache --download-cue-model
```

Команда CPU опубликована в [официальной таблице PyTorch 2.3.1](https://pytorch.org/get-started/previous-versions/#v231); для macOS или CUDA используйте соответствующую строку той же таблицы. Проверенный комплект — torch/torchaudio 2.3.1, torchvision 0.18.1 и NumPy 1.26.4. Не заменяйте его автоматически новейшим PyTorch: текущий Demucs требует torch ниже 2.6. Другие допустимые пары 2.4/2.5 требуют собственной проверки. Подробности — [engines.md](engines.md).

`setup` получает закреплённые checkouts audamcp и Bitwize, веса Beat This! `final0` и три проверенных файла CUE-DETR. `--cache` задаёт кэш Beat This!; CUE-DETR сохраняется в `~/.cache/superdj/cue-detr`. [Demucs](https://github.com/facebookresearch/demucs) получает официальные веса `htdemucs` при первом включённом распознавании и хранит их в приватном кэше PyTorch. Поэтому успешный `setup` ещё не означает, что веса Demucs уже есть для работы без сети. Музыкальное распознавание выполняется локально. Исполняемые инструменты и веса не включены в этот репозиторий; лицензии перечислены в [THIRD_PARTY.md](../THIRD_PARTY.md).

## Приватная конфигурация

Возьмите [assets/runtime-zhilin.example.json](../assets/runtime-zhilin.example.json) как пример и создайте `~/.cache/superdj/runtime.local.json`. Замените каждый пример пути реальным абсолютным путём; файл примера не загружается автоматически. В Windows используйте `/` или двойные `\\` в JSON. Если конфигурация уже существует, сохраните её резервную копию и обновите только нужные поля.

Основные поля:

| Поле | Что указать |
| --- | --- |
| `audamcp`, `bitwize` | Два checkout, созданные `setup` |
| `ffmpeg`, `ffprobe`, `rubberband`, `git` | Реальные исполняемые файлы либо имена в PATH |
| `cache`, `private_output_root` | Приватные промежуточные данные и отчёты вне checkout |
| `delivery_root` | Ваша папка готовых FLAC/CUE |
| `track_history` | Ваша новая приватная история; импортируйте только свои готовые CUE |
| `default_style` | `zhilin` для обычных запросов в этом режиме |
| `zhilin_profile` | Абсолютный путь к `assets/zhilin-reference-v1.json` выбранной версии |
| `cue_model` | Каталог `~/.cache/superdj/cue-detr` после загрузки |
| `cue_python`, `stem_python` | Python окружения с соответствующей моделью |
| `beat_checkpoint`, `beat_device`, `cue_device`, `stem_device` | `final0` и доступное устройство; `cpu` — переносимый вариант |

Переносимый профиль содержит 257 точек одобренных нормализованных огибающих и положение передачи баса. Это именно сохранённая форма одобренных кривых, а не автоматически выбранная запасная кривая. Он не содержит музыку, исходные хеши, имена, монтажные точки, отзывы или историю. Сохраните `zhilin_profile` явно: один `default_style: zhilin` выбирает режим, но без профиля использует широкую резервную огибающую. Индивидуальные отзывы `adaptive_mid_feedback` не нужны для установки; новые отзывы храните отдельно и приватно.

Проверьте `superdj --help`, `superdj make --help`, доступность внешних инструментов и импорт установленных пакетов. Это проверяет подготовку, но не заменяет рендер и измерения первого настоящего сета. В его отчёте должны быть фактически выполненные модели, версии, профиль и исходники. Сохранённая версия кода, настройки, выбор треков и проверки нужны для повторения собственной сборки; другое устройство или музыка могут дать другой результат.

## Запрос собрать 20 треков

После подготовки вставьте запрос, заменив путь папки:

```text
Используй $ai-super-dj. Собери сет ровно из 20 моих треков из папки
«ПУТЬ К МОЕЙ МУЗЫКЕ» в режиме DJ Жилин с настроенным переносимым
профилем. Обнови историю из моей папки готовых сетов и выбери 20
неиспользованных треков, сохрани приватный список выбора и порядок.
Если их меньше 20, сообщи точное число и не добавляй повторы самовольно.
Если я дам порядок, крайние треки или согласованные точки, сохрани их.
Иначе выстрой музыкальное развитие от более лёгкого начала к насыщенному
финалу с учётом совместимости, темпа и участков сведения.
Используй общий SYNC. Предпочитай 32 такта и длинную полезную середину,
а 16/8 выбирай при подтверждённой конкуренции голосов или мелодий;
различие нотных профилей само по себе не повод сокращать переход.
Настраивай бас отдельно. Проверь распознанные ведущие атаки и реальное
сведённое аудио; при подтверждённом раннем верхнем фронте используй
предусмотренную передачу всего спектра ударных через свежий Demucs.
Сохрани FLAC 24 bit и CUE в моей папке готовых сетов, отчёт и промежуточные
данные — приватно. Покажи выполненные проверки, исключения и места,
которые требуют моего прослушивания.
```

Сам `make` получает все подходящие файлы папки после фильтра истории. У него нет аргумента «20 треков»: агент сначала формирует явный список из двадцати, затем передаёт его движку. Случайный выбор выполняйте только по запросу, с сохранённым seed. Одна и та же музыка и seed требуют также одинаковой истории и списка доступных файлов. Запуск `make` на папке из ста файлов не является выбором двадцати.

Обычный F/SYNC передаёт бас за четыре доли и середину за 8–16 долей. DJ Жилин сохраняет широкую середину и обычно передаёт бас за одну восьмую наложения — около четырёх тактов при 32 тактах. Проверка ведущих атак действует в обычном SYNC; автоматическая передача всего спектра ударных включается в DJ Жилин только при подтверждённой ранней верхней атаке и требует Demucs. В этом случае проверяется также итоговое наложение, сохраняются распознанные события и возможная малая локальная поправка всего сведённого сигнала. Поправка требует свежих проверок и нового мастера; успешное выравнивание отдельных дорожек не означает автоматически успешный итоговый микс. Результат оценивается по распознанным событиям и прослушиванию; неизвестные транзиенты не считаются проверенными. [Границы проверки](acoustic-sync.md).

Этот запрос повторяет переносимый способ работы. Он не переносит чужой выбор двадцати файлов, ручные точки и поправки конкретных пар. Для точного повторения уже готового монтажа нужны те же исходники, сохранённый порядок, согласованные точки и overrides; на другой коллекции итоговое звучание оценивается заново.

## Отдельный запрос сравнить порядок с DJ.Studio

В Python-пакете уже есть два лёгких профиля порядка; для них не нужна чужая приватная конфигурация или загрузка нейросетевых весов. Их числовые параметры зафиксированы, а тренировочные источники и отзывы не включены. Для полного порядка попросите «сравни с DJ.Studio через `djstudio-route-v1`», для локальных рекомендаций — «предложи следующий трек через `djstudio-next-v1` с моим фактическим сыгранным списком». Примеры команд — [harmonize.md](harmonize.md).

Эти профили отражают текущий компромисс, без универсального победителя: локальный Top3, соседи и полные цепочки требуют разных проверок. Часть источников последнего сравнения уже встречалась в обучении; независимая проверка на новой музыке не заявляется. Неизвестный внутренний список DJ.Studio нельзя восстановить из нескольких наблюдённых выборов.

Для повторения сохранённого сравнения использовались seed 0, нейтральное направление, свободные крайние треки и явно подтверждённые условия: Mood/BPM с допуском 4, Fuzzy/BPM с допуском 6 либо Key с отключённым допуском. На своей задаче задайте свои условия явно. Допуск — предпочтение в оценке, а не запрет любого большего скачка. Профиль выбора порядка, обычное развитие сета и стиль сведения DJ Жилин — отдельные решения; обычный запрос из двадцати треков выше сохраняет обычный музыкальный планировщик.
