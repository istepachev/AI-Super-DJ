# Исправления и переносимость

Нижняя граница полной игры — одна минута. Варианты 1:50 и 1:30 не останавливают сборку. До двух минут выполняется попытка музыкального лупа; отсутствие подходящего стыка сохраняет исходную короткую игру. Новый луп полностью обратим: кроме копируемой фразы сохраняется исходный изменённый контекст стыка с контрольной суммой. Старый манифест с техническим минимумом 120 секунд не превращает его в пользовательское закрепление.

Плавность — общее правило всех обычных стилей и Mood/Classic/Fuzzy. При пересборке проверяются фактические кривые баса, середины и ударных; автоматическая последовательная смена ударных не считается исправлением. При конфликте атак движок сначала может проверить до трёх других положений той же плавной передачи внутри неизменного наложения. Длина передачи, исходные участки, темп и кривые середины/верхов сохраняются; явные настройки положения или длительности передачи баса не меняются. Если конфликт остаётся, выбирается другой допустимый участок с полным новым рендером. Ритмические допуски, длительности и пользовательские закрепления не ослабляются.

Обычная сборка проверяет фактическое наложение на продолжительную потерю энергии и баса относительно доступного звука обеих дорожек. Короткие сбивки и тихий участок, присутствующий в обоих исходниках, сами по себе не считаются дефектом. Проверка оценок голоса учитывает применённую передачу переднего плана. Разделение приблизительное; отсутствие двух оценок означает неизвестность, а не доказанное отсутствие вокала.

Покрытие распознанных ритмических событий используется внутри движка. Несколько удачных совпадений не подтверждают длинный плохо распознанный переход. Эти сведения сохраняются в приватном манифесте; отдельный отчёт человеку не требуется. Показатели не являются вероятностью музыкального качества.

Если недостаточное покрытие однозначно относится к одной дорожке и одному краю, передавай её идентификатор и роль в поиск нового окна. Не сдвигай другую дорожку с достаточным покрытием вместо известного проблемного источника. При недостаточном покрытии обеих дорожек или только при ошибке энергии/голоса не назначай единственного виновника; сохраняй полные независимые показатели.

После ошибки подходящего автоматического окна сборщик может сделать до двух дополнительных попыток: передвинуть незакреплённую точку в пределах шестнадцати тактов исходника. Сохраняются порядок, длина перехода, защищённые участки и бюджет звучания трека. Каждая попытка заново рендерится и проходит обычные проверки. Позиции пропущенных обязательных басовых атак, включая независимо видимые оценки ударных, и распознанных атак с недопустимым опозданием исключаются по времени исходника: смена относительного номера доли не делает такое же окно новым. Ошибка диска, декодера или конфигурации не лечится сменой музыкального окна. При невозможности выполнить ограничения сборка останавливается.

## Исправить один переход

При полной пересборке отказ на конкретном выходе требует другого выхода: перенос начала той же записи не делает прежнее неисправное окно новым. Учитывай отвергнутые границы по времени исходника даже при нулевом покрытии, когда списка распознанных плохих атак нет. Автоматические параметры старого монтажа не становятся пользовательскими закреплениями; при новом выборе монтажа фиксируй новые решения явно и заново проверяй весь звук.

Для полного нового монтажа API `superdj.source_search.fresh_arrangement_alternative` сохраняет исправные границы, отвергает повтор уже неудачной границы и допускает короткую игру от 60 секунд, сохраняя цель 3–4 минуты. Его план всё равно требует полного нового рендера; API не является проверкой звука или автоматическим разрешением менять пользовательские закрепления.

Нераспознанное после растяжения окно сохраняет идентификатор реально сбойной дорожки и её входящую/исходящую сторону. Если не подтверждены обе стороны, переподбор всё равно относится к этой записи; смена соседнего трека не считается исправлением её ошибки.

Первичный подбор полного нового сета может согласованно уменьшить два соседних автоматических окна, когда изменение только одного ещё не даёт места для музыкального ядра. Это поиск допустимого исходного плана до рендера. Явные длины переходов и последующее восстановление уже выбранного перехода сохраняют свои ограничения; проверки фактического звука не ослабляются.

```powershell
superdj revise --manifest "../results/set_manifest.json" --transition track_07 track_08 --output "../revisions" --name "set_revision"
```

Выбирается другое допустимое окно той же пары. Порядок сохраняется. Обе закреплённые точки не передвигаются автоматически. Старый файл и его манифест остаются на месте.

## Удалить трек

```powershell
superdj revise --manifest "../results/set_manifest.json" --drop track_08 --output "../revisions" --name "set_without_08"
```

Можно перечислить несколько идентификаторов после `--drop`. Порядок до первого удаления сохраняется. Остаток заново подбирается существующим гармоническим алгоритмом с последним сохранённым треком в качестве начала; все новые соседства получают новые оценки. Гармония остаётся частью общей функции качества, а не обещанием идеальной совместимости любого набора.

Сохраняются выбранные Mood/Classic/Fuzzy, энергетическая кривая, ограничения темпа и явные ограничения монтажа. Закреплённый переход между оставшимися треками нельзя молча разорвать ради нового порядка. Такой конфликт требует отдельного изменения ограничения. Пользовательская энергетическая кривая произвольной длины требует новых явных позиционных целей.

Манифест позволяет переиспользовать анализ только при совпадении SHA-256 исходников. Изменённый источник требует нового анализа. Недоступные оценки голоса и ударных восстанавливаются тем же настроенным разделителем и весами. Проверенные этапы постоянного кэша переиспользуются по обычным правилам. Без постоянного кэша старые временные звуковые файлы не обещаются доступными между запусками; анализ из манифеста всё равно проверяется по исходникам.

После любого изменения создаются новый общий мастер и новый FLAC с полным контролем. Исходный сет не перезаписывается. Тесты и отчёты остаются в приватной папке. Выбор заданного количества треков этим обновлением не добавляется.

## Ресурсы

`make`, `run`, `render` и `revise` оценивают память и место до основной обработки. Свободное место суммируется для папок на одном томе. Число параллельных задач ограничивается доступной RAM, числом потоков CPU и настроенными устройствами. Недоступная явно настроенная GPU или явная нехватка памяти/диска дают понятную ошибку; алгоритм не снижает частоту дискретизации, разрядность или точность моделей. Для работы на CPU нужно настроить CPU в установленной среде.

Оценки имеют запас, но не резервируют ресурсы у операционной системы. Неизвестные показатели остаются неизвестными, а предполагаемое высокое потребление памяти записывается в приватный `performance.json`. Постоянный звуковой кэш по умолчанию остаётся выключенным.
