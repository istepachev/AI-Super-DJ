# Исправления и переносимость

Обычная сборка проверяет фактическое наложение на продолжительную потерю энергии и баса относительно доступного звука обеих дорожек. Короткие сбивки и тихий участок, присутствующий в обоих исходниках, сами по себе не считаются дефектом. Проверка оценок голоса учитывает применённую передачу переднего плана. Разделение приблизительное; отсутствие двух оценок означает неизвестность, а не доказанное отсутствие вокала.

Покрытие распознанных ритмических событий используется внутри движка. Несколько удачных совпадений не подтверждают длинный плохо распознанный переход. Эти сведения сохраняются в приватном манифесте; отдельный отчёт человеку не требуется. Показатели не являются вероятностью музыкального качества.

После ошибки подходящего автоматического окна сборщик может сделать до двух дополнительных попыток: передвинуть незакреплённую точку в пределах шестнадцати тактов исходника. Сохраняются порядок, длина перехода, защищённые участки и бюджет звучания трека. Каждая попытка заново рендерится и проходит обычные проверки. Ошибка диска, декодера или конфигурации не лечится сменой музыкального окна. При невозможности выполнить ограничения сборка останавливается.

## Исправить один переход

```powershell
superdj revise --manifest "../results/set_manifest.json" --transition track_07 track_08 --output "../revisions" --name "set_revision"
```

Выбирается другое допустимое окно той же пары. Порядок сохраняется. Обе закреплённые точки не передвигаются автоматически. Старый файл и его манифест остаются на месте.

## Удалить трек

```powershell
superdj revise --manifest "../results/set_manifest.json" --drop track_08 --output "../revisions" --name "set_without_08"
```

Можно перечислить несколько идентификаторов после `--drop`. Порядок до первого удаления сохраняется. Остаток заново подбирается существующим гармоническим алгоритмом с последним сохранённым треком в качестве начала; все новые соседства получают новые оценки. Гармония остаётся частью общей функции качества, а не обещанием идеальной совместимости любого набора.

Сохраняются выбранные Mood/Classic/Fuzzy, энергетическая кривая, ограничения темпа и явные ограничения монтажа. Закреплённый переход между оставшимися треками нельзя молча разорвать ради нового порядка. Такой конфликт требует отдельного изменения ограничения. Пользовательская энергетическая кривая произвольной длины требует новых явных позиционных целей.

Манифест позволяет переиспользовать анализ только при совпадении SHA-256 исходников. Изменённый источник требует нового анализа. Недоступные оценки голоса и ударных восстанавливаются тем же настроенным разделителем и весами. Проверенные этапы постоянного кэша переиспользуются по обычным правилам. Без постоянного кэша старые временные звуковые файлы не обещаются доступными между запусками; анализ из манифеста всё равно проверяется по исходникам.

После любого изменения создаются новый общий мастер и новый FLAC с полным контролем. Исходный сет не перезаписывается. Тесты и отчёты остаются в приватной папке. Выбор заданного количества треков этим обновлением не добавляется.

## Ресурсы

`make`, `run`, `render` и `revise` оценивают память и место до основной обработки. Свободное место суммируется для папок на одном томе. Число параллельных задач ограничивается доступной RAM, числом потоков CPU и настроенными устройствами. Недоступная явно настроенная GPU или явная нехватка памяти/диска дают понятную ошибку; алгоритм не снижает частоту дискретизации, разрядность или точность моделей. Для работы на CPU нужно настроить CPU в установленной среде.

Оценки имеют запас, но не резервируют ресурсы у операционной системы. Неизвестные показатели остаются неизвестными, а предполагаемое высокое потребление памяти записывается в приватный `performance.json`. Постоянный звуковой кэш по умолчанию остаётся выключенным.
