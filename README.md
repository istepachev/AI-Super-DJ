# AI Super DJ

AI Super DJ — AI-навык и локальный процесс создания и проверки DJ-сетов: анализ треков, подбор последовательности, подготовка переходов, выборочная реставрация, мастеринг, проверенный FLAC-экспорт и аудит проектов DJ.Studio.

Проект объединяет роли музыкального анализа, DJ-планирования и аудиообработки. Код внешних навыков подключается отдельными адаптерами; это не копия двадцати инструкций и не двадцать одновременно работающих мастерингов.

## Два режима

| Режим | Что делает |
|---|---|
| `fixed` | Сохраняет заданный пользователем порядок и выбирает технику для каждого перехода. Сложный стык остаётся видимым в плане. |
| `auto` | Предлагает порядок по гармонической совместимости, темпу, развитию энергии и доступным местам переходов; учитывает закреплённые позиции. |

Подбор следующего трека — часть оценки всей последовательности. До 17 треков включительно используется точный Held–Karp для заданной функции стоимости; для большего числа — ограниченный beam search с улучшением сегментов. План сохраняет причины выбора, ограничения, сравнение с жадным baseline и неопределённость анализа. Численный оптимум не гарантирует лучший результат на слух. Это собственный объяснимый подход; внутренний алгоритм DJStudio Harmonize AI здесь не воспроизводится.

## Процесс

1. Проверить источники, темп, тональность, энергию и музыкальную структуру.
2. Подготовить порядок и места переходов. Проверить первые доли тактов и границы фраз отдельно от обычного beat tracking.
3. Исправить только обнаруженные дефекты, сравнив обработку с оригиналом при одинаковой громкости.
4. Свести треки с запасом по уровню, контролем баса/вокала и умеренным изменением темпа.
5. Сделать мастеринг полного сета и независимо проверить конечный файл.

В 4/4 переход на 16 тактов занимает 64 удара. Эта арифметика сама по себе не определяет начало музыкальной фразы: сомнительные сетки и точки требуют проверки. Опциональная нейросеть [Beat This!](https://github.com/CPJKU/beat_this) предсказывает удары и первые доли тактов на полном треке; её результаты помечаются как предсказанные. Ручная проверка сетки и границ фраз учитывается отдельно. Облегчённый librosa-анализ даёт только оценочные удары. Проект не обещает безошибочное автоматическое сведение любого материала по квадратам.

Промежуточный формат — явно заданный 32-bit float WAV; финальный мастер Bitwize — 24-bit WAV, затем явно заданный 24-bit FLAC. Начальный профиль работает в stereo 44.1 kHz: источники с другой частотой пересчитываются. MP3 можно создать как дополнительную копию для прослушивания. Перевод MP3 в FLAC сохраняет обработанный результат без новых потерь, но не восстанавливает детали, удалённые MP3-кодеком.

## Установка и использование

Нужны Python 3.12+, FFmpeg и FFprobe. Для качественного изменения темпа отдельно устанавливается Rubber Band CLI. Python-зависимости и доступные команды описывает `pyproject.toml`; фактические параметры показывает `python -m superdj --help` после установки проекта.

```text
python -m pip install -e .
python -m superdj --help
```

Для нейросети и выборочной реставрации: `python -m pip install -e ".[grid,repair]"`. Установка PyTorch/torchaudio должна соответствовать CPU или CUDA вашей системы; веса модели загружаются отдельным явно включаемым действием в приватный кэш. Сам навык не загружает обучение или музыку.

Командные этапы: `analyze`, `plan`, `render`, `run`; `setup` готовит закреплённые внешние checkouts. В `fixed` передайте свой порядок; в `auto` — выбранные треки и ограничения. Можно выбрать случайные треки из заданной папки, сохранив seed для повторения. Реальные плейлисты, результаты анализа, checkouts, веса и аудио храните **вне репозитория**; CLI запрещает рабочие артефакты внутри него.

Пример с отдельной рабочей папкой рядом с репозиторием, установленными аудиоинструментами и выбранными Python-зависимостями:

```text
superdj setup --components ../superdj-work/checkouts --download-model --cache ../superdj-work/cache
superdj run --folder ../music --count 15 --seed 2026 --mode auto --work ../superdj-work/session --cache ../superdj-work/cache --output ../superdj-work/output --audamcp ../superdj-work/checkouts/audamcp --bitwize ../superdj-work/checkouts/bitwize --rubberband rubberband
```

Для собственного списка используйте `--playlist ../superdj-work/playlist.json --mode fixed`. Формат списка: объект `tracks` с элементами `{ "id": "track_01", "path": "../music/track_01.flac" }`; пути разрешаются от текущего каталога запуска. Необязательный `--fixed-order` получает отдельный JSON-массив всех `id` в нужном порядке. `--first` и `--last` закрепляют крайние треки автоматического порядка. `--grid-json` задаёт импортированные сетки по `id`; `--allow-unverified` разрешает явно помеченные короткие свободные переходы при неопределённых сетках.

Начальные окна можно искать с пропуском до 32 секунд вступления (`--max-intro-trim-seconds`). Причина и точное время обрезки сохраняются. Повторный запуск сохраняет предыдущие промежуточные файлы в рабочем каталоге; замена готового аудио требует явного `--overwrite`.

Для Codex установите репозиторий как навык с именем `ai-super-dj` или поместите его папку в каталог пользовательских навыков, затем используйте `$ai-super-dj`. [SKILL.md](SKILL.md) — точка входа, [workflow](references/workflow.md) — подробный порядок действий. Установка самого навыка не устанавливает аудиопрограммы и модели автоматически. Python-модуль `superdj` и прежняя команда сохранены для совместимости; новая команда — `ai-super-dj`.

По умолчанию `sync` ведёт оба трека по одной кривой темпа и одной фазе долей на всём наложении. Темп меняется от исходного темпа старого трека к исходному темпу нового внутри перехода; основные части остаются на своей скорости. При большой разнице используются четыре общих такта (`--sync-transition-bars`), отдельный предел кратковременной коррекции — 40% (`--sync-max-change`). Новый трек при этом может кратко войти быстрее исходной скорости. Это вариант для прослушивания, а не обещание оптимального результата. Для независимой проверки атак есть консервативный анализ готового PCM и компенсация измеренной задержки обработки; неоднозначные атаки остаются непроверенными.

Для частичного совпадения ритмов есть отдельный модуль `superdj.polyrhythm`: например, четыре старых удара на три новых, небольшая правка только выхода старого трека и фильтрация частотных полос. Это доступно через явный сценарий рендера, пока без автоматического выбора в CLI. Новый трек сохраняет исходную скорость. Ни эта техника, ни пластинка не выдаются за непрерывное совпадение всех ударов 1:1.

Прежние варианты выбираются явно: `adaptive` — выход старого трека под виниловое замедление, `shared_tempo` — постоянный средний темп с рампами до/после наложения, `echo_bridge` — последовательная передача сухого звука через эхо. Винил и эхо не являются непрерывным SYNC 1:1. Мягкий общий темп ограничен 6%; расширение старого эксперимента задаёт `--tempo-ramp-max-change`. Неизвестный темп или недостаточная сетка требуют проверки. `review` оставляет нерешённые переходы для выбора техники; резкий стык и свободный короткий фейд требуют явных соответствующих опций.

Точные входы и выходы можно закрепить в `cue_locks` каждой пары плана. Закреплённая точка должна совпадать с имеющейся сеткой начал тактов и допустимыми пределами обрезки: рендер либо соблюдает её, либо сообщает ошибку. Автоматическое обнаружение подходящих брейков, защищённые музыкальные участки и минимальное время слышимого присутствия каждого трека ещё требуют доработки.

Для `plan` и `run` файл таких ограничений передаётся через `--transition-overrides`: массив `{from,to,cue_locks}` для реально соседних пар. `render` читает ограничения из готового плана. Фиксация выбранной границы исходника не гарантирует полную слышимость в этой точке: эхо-переход сначала оставляет входящий прямой звук под эффектом, затем плавно вводит его. Отчёт сохраняет это время отдельно.

Для существующего монтажа DJ.Studio доступен адаптер чтения и проверки `.djs` и CUE. Он сохраняет исходные параметры переходов в отчёте, сверяет порядок с экспортом и отделяет метки глав от полного времени звучания треков. Подробности и ограничения — в [DJ.Studio workflow](references/djstudio.md). Адаптер не пересобирает монтаж и не меняет архив; режим «своди как DJ Жилин» отложен.

## Внешние компоненты

Предпочтительные роли: audamcp/dpf-audio-pro для выборочного исправления дефектов, Bitwize для финального мастеринга, Rubber Band для темпа, FFmpeg для кодеков и проверок. Точные ревизии и лицензии приведены в [THIRD_PARTY.md](THIRD_PARTY.md). Внешние компоненты не входят в исходный репозиторий и не могут считаться использованными только потому, что они установлены.

## Что считается готовым сетом

Готовый результат содержит аудиофайл, треклист с временем, план переходов, описание реально выполненной обработки и отчёт проверки. Проверяется полное декодирование, формат/разрядность, порядок и число треков, громкость в LUFS, sample peak в dBFS и независимый oversampled true peak в dBTP. Начальные цели: −14 LUFS и потолок мастеринга −1.5 dBTP; экспорт дополнительно проверяет максимум −1.0 dBTP. Фактические значения сохраняются в отчёте, поскольку громкость может уступать ограничению пиков. Переходы дополнительно проверяются прослушиванием.

Проверка синтетических сигналов подтверждает работу механизмов. Проверка реального музыкального сета — отдельный этап перед первоначальной публичной публикацией.

В репозиторий входят код, инструкции и тесты на создаваемых сигналах. Пользовательская музыка, абсолютные пути к ней, плейлисты, замеры, кэши, веса моделей и секреты остаются локальными.

Тесты запускаются после `python -m pip install -e ".[test]"` командой `python -m pytest -q`. Проверки настоящего аудиорендера требуют FFmpeg, FFprobe и Rubber Band в `PATH`; иначе задайте `SUPERDJ_FFMPEG`, `SUPERDJ_RUBBERBAND`, `SUPERDJ_TEST_FFMPEG`, `SUPERDJ_TEST_FFPROBE`. Без этих инструментов внешние проверки пропускаются, что видно в результате тестов.
